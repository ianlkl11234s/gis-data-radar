## 近期平台更新：Google Places Insights

<a id="google-places-insights"></a>
ID：`google-places-insights`｜data_platform／dataset／showcase｜台灣、日本、其他支援國家｜urban、POI、time-series

[發布紀錄](https://developers.google.com/maps/documentation/placesinsights/release-notes)列：2026-09-02 月度歷史快照與 PLACES_COUNT_CHANGE 正式可用，可回看至 2024-01；台灣已於 3/12 加入。首次 Preview 為 2025-04-01，本期發現／查核 2026-10-05；9/28 頁尾更新不當成新功能發布日。

- 範圍與格式：BigQuery 資料與 SQL 表值函數；台日均有[國別 schema](https://developers.google.com/maps/documentation/placesinsights/reference/country-schema)，但行政欄位不同，不能假設台灣具有日本同等地址層級完整度
- 顆粒度：[Count 函數](https://developers.google.com/maps/documentation/placesinsights/overview)支援自訂區域／H3，最小搜尋面積 1,600m²；這不是定位精度。直接 SQL 聚合省略 0–4 筆的列，省略值不能當零；函數可回低計數及樣本 Place IDs，並非完整店家名冊
- 時間：月快照適合跨期比較；當前內容定期刷新，未量測延遲
- 費用：[官方價格頁](https://developers.google.com/maps/documentation/placesinsights/quota-and-pricing)要求洽業務，沒有可直接套用的公開單價。評估預算須再確認資料方案、BigQuery 計算及另用 Places API 的費用，不能拿一般 Places API 單價代入
- 權利：[政策](https://developers.google.com/maps/documentation/placesinsights/policies)要求依服務協議及 Google Maps 顯名使用。它是商用資料服務；文件的開放授權不授予資料自由再散布。公開圖層、快取及非 Google 底圖的適用條件仍需核對實際合約
- 難度：中至高；未申請存取、未執行 SQL、未下載受限制原始資料

**推薦 1：先研究固定區域的月度 POI 變化。** 例如台北與一個日本城市，各固定範圍、類別與月份。[變化函數](https://developers.google.com/maps/documentation/placesinsights/place-count-functions/places-count-change)提供起訖數、淨變化及新增／移除樣本；樣本數不等於完整新增／關店數。資料維護也可能造成變化，須抽樣查證，不能直接等同真實開店潮。正式導入先通過費用與權利評估；也可先用已具授權的本地 POI 實作比較設計。

### 展示案例：讓時間條件真正影響地圖

[官方 Data Studio 教程](https://developers.google.com/maps/architecture/places-insights-looker-studio)展示城市、星期與時段選單連動餐飲密度圖；頁面更新 2026-09-30，首次發布未知。值得借鑑的是「明確條件 → 聚合結果 → 地圖」流程，並標清被門檻省略的格子。此處時段反映登錄營業時間，不是即時人潮。

這是公開教程／展示設計參考，未操作線上互動；demo 入口的文字擷取只有導覽，故不把它當已驗收案例。不為同一服務另外建立重複資料源。

## 既有方法／工具：H3 密度與邊界核算

<a id="h3-density-boundary-accounting"></a>
ID：`h3-density-boundary-accounting`｜analysis_method／model_tool｜不限地區｜urban、population、POI、data-quality

[H3 polygonToCells](https://h3geo.org/docs/api/regions/)用格心決定入選；實驗性 overlap 模式納入相交格，兩者都不會自動分配人口。另依[官方格網統計](https://h3geo.org/docs/core-library/restable/)，同解析度格子仍有面積差異，因此不能一律用平均面積作密度分母。

**推薦 2：優先為現有 H3 做一個沿岸／行政邊界小樣本驗算。** 逐格用 [cellArea](https://h3geo.org/docs/api/misc/#cellareakm2) 取得球面面積；若算陸域密度，先讓分子與裁切後的陸域分母一致。面狀人口轉格若採交集面積加權，應揭露均勻分布假設並檢查總量守恆。這是本報提出的驗收方法，未檢查或判定既有算法有錯。

- 實作：官方 H3 API；[程式 Apache 2.0](https://github.com/uber/h3/blob/master/LICENSE)，輸入人口／POI 仍各依原授權
- 發布與更新日未知；發現／查核 2026-10-05
- 難度低至中；無須新增第三方付費資料就能先做
- 高解析度不會增加原始人口資料精度；選格與裁切的差異須明示。未實跑、未測效能
